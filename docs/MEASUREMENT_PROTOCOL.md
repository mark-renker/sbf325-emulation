# Measurement protocol

All fidelity claims are produced by `measure/*.py` from WAV files; nothing is judged by ear.
`measure/run_all.py` renders the stimuli through the standalone renderer (`sbf_render`), analyses them,
writes `docs/results/results.json` and `docs/results/RESULTS.md` (with plots), and exits non-zero if any
Section 8 gate fails. `make -C measure verify` builds the renderer and unit tests first.

Capture rate 96 kHz; the renderer writes 32-bit float. Stimuli are generated by the renderer itself so
the scripts are self-contained (`--gen sweep|sine|impulse|burst|silence|noise`).

## Hardware captures (when a unit is available)

Capture per channel and per mode at 96 kHz / 24-bit, through the same converter chain for dry and wet:

1. Swept sine 20 Hz–20 kHz, 4 s, −12 dBFS, LFO depth 0, MANUAL = 0.5 / 1 / 2 / 5 / 10 / 15 ms.
2. Same with FEEDBACK = 25 / 50 / 75 / 100 %.
3. LFO output at CP‑2 (DC-coupled) at RATE 0, 2.5, 5, 7.5, 10 plus the ±peak LED timing.
4. Impulse / click responses for delay measurement at the 11 MANUAL points per range.
5. 1 kHz level sweep −40 … 0 dBFS in 5 dB steps for THD+N.
6. Silence for the noise floor.
7. 30 s programme clip per mode for the null test.

Put them under a directory and pass `--reference <dir>`; the scripts look for:

| File | Content |
|---|---|
| `delay_law.csv` | `mode,manual_ms,delay_us` (mode = fl2 / chorus) |
| `bandwidth.csv` | `manual_ms,f3db_hz` |
| `mode_matrix.csv` | `coef,db` for own / cross / dry |
| `feedback_peak.csv` | `manual_ms,peak_db` |
| `compander.csv` | `attack_ms,release_tau_ms` |
| `thd.csv` | `level_dbfs,thdn_db` |
| `<case>_dry.wav`, `<case>_wet.wav`, `<case>.json` | null-test pairs; the json holds `{"args": [renderer parameters]}` |

Measurement data from your own unit may be published under CC0 or CC‑BY (state which in the commit).

## Tests and gates (spec §8)

| Script | What it measures | Gate |
|---|---|---|
| `delay_law.py` | Wet-path delay vs MANUAL, 11 points × 2 ranges (impulse cross-correlation, latency removed) | ≤ 3 % of reading vs reference (hardware, else model nominal + analog group delay) |
| `bandwidth.py` | −3 dB point of the wet path at 6 settings (sweep deconvolution, 1/24-oct smoothed) | ±10 % vs hardware; without captures: 14 kHz ±10 % at 0.5 ms and no shrink with faster clock |
| `mode_matrix.py` | FLANGER III own/cross/dry at 1 kHz with signal in A only; FL I/II routing | ±0.5 dB |
| `feedback_ceiling.py` | FEEDBACK 100 % at 6 settings: decay after a burst; comb peak gain from a −30 dBFS sweep | no self-oscillation (tail < −60 dBFS); peak ±1 dB vs hardware |
| `compander.py` | Noise-floor envelope (>3 kHz) around a 1 kHz burst: release τ (log-slope fit), attack settle | τ within 20 % of reference (hardware, else declared) |
| `lfo.py` | Rate at 0.02 / 0.3 / 5 Hz, triangle correlation, LED flags vs peaks | rate ±5 %, triangle, LEDs at peaks |
| `thd.py` | THD+N vs level, 1 kHz, FL II at 15 ms (harmonics on comb peaks) | finite; ≤ −50 dB at −20 dBFS; hardware curve when present |
| `aliasing.py` | 10 / 15 kHz at DEPTH 100 %, RATE 5 Hz; alias search below the Doppler band | ≤ −80 dBFS at −12 dBFS input; 0 dBFS reported |
| `noise_floor.py` | Broadband output noise, silence in | < −70 dBm (−90 dBFS) noise on; < −120 dBFS noise off |
| `null_test.py` | Model vs hardware wet, aligned and gain-matched | residual < −30 dB (skipped without captures) |
| `cpu.py` | Per-instance CPU at 48 kHz / 64 samples; reported latency | informational; latency = 4 samples exactly |
